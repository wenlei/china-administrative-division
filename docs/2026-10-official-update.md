# 2026年10月官方数据更新

本批于2026-10-20整理，沿用原有 `patches/<年份>/*.json` 协议。目标分区是2026，基线为2023；旧补丁和旧年度源文件均保留。不新增第二套区划库。

## 数据口径

- 官方六位省市县码、九位乡级码统一尾补零为原协议的十二位码。直辖市保留原有中间占位节点以兼容查询。
- 江苏等省的NBS统计码与民政码存在同码异名、同名异码。补丁校准2026目标分区；2023及更早历史名称不被覆盖。
- 完整官方名录以外的旧统计节点在2026分区标记 `deprecated`，不物理删除；这表示退出本批民政四级视图，不等于断言统计单位实体已经撤销。未取得全量的省份不执行此类退出操作。
- 村级仍为冻结的2023历史记录。乡级码调整后，村级隶属不能作为2026现势使用；本批闭合检查只覆盖省、市、县、乡四级。
- 江西“（门+合）山镇”、福建“虎氵贝镇”等拆字按原文保留，未臆造字符或名称。
- 来源页面路径可能沿用旧年月，应以正文或附件的截止日期为准。上海只明示2026-07-27发布日，未推断为数据截止日。
- 每份补丁 `meta.notes` 和来源清单保存原件SHA-256。PDF同时校验原PDF和 `pdftotext -layout` 提取结果。动态网页以后重新下载可能字节不同，须按新的原件重新审查，不能沿用旧校验值。

## 重建本批更新

先构建CLI并导入2023基线；下载的大CSV、SQLite不提交Git，沿用原项目NPM/Release数据分发方式。

```bash
pnpm install --frozen-lockfile
pnpm --filter @cndiv/cli build
node packages/cli/dist/cli.js hydrate --year=2023 --cache=/path/baseline
node scripts/materialize-official-update.mjs \
  --baseline=/path/baseline/cache.db \
  --sources=updates/2026-10.sources.json \
  --output=/path/new-october-output
```

输出目录必须不存在。脚本先在独立临时目录保留输入库除目标2026以外的所有历史分区，按清单顺序重放2024、2025事件、已有2026合并补丁、19省官方补丁及湖南10月公告。不能用通配符无序重放，也不能只应用旧的 `2026.merged.json`。

仅在以下检查全部通过后，才通过目录重命名发布 `cache.db`、`coverage.json` 和 `replay.log`：

1. 每个补丁均通过原协议校验，且声明2023基线。
2. 所有输入历史分区逐字段保留，目标2026之外无变化。
3. 有效四级节点的父级存在且有效。原来重庆撤区后42个乡级挂旧父级的问题由官方名录校准消除；未猜测下级迁移。
4. 19省级地区乡级数量与官方表一致；湖南额外6条公告单列校验。
5. SQLite完整性、补丁审计条数一致。

`coverage.json` 明示 `complete_national=false` 和全部未取得省份；`--require-complete` 在存在缺口或旧版/无日期表时拒绝构建，不会把混合时点数据发布为完整现势全国库。

需要导出时，可继续使用原有CLI：

```bash
node packages/cli/dist/cli.js export --year=2026 --cache=/path/new-october-output --output=/path/2026.csv
```

原有导出包含村级历史记录及deprecated节点。消费现势四级时须按 `year=2026 AND level<=4 AND status='active'` 筛选，并同时读取覆盖元信息。

## 从原件重新生成补丁

安装 `beautifulsoup4 xlrd openpyxl`。按 `updates/2026-10.sources.json` 的文件名保存本批原件，PDF需先 `pdftotext -layout` 转为清单指定TXT；不要用OCR猜测未核验省份。

```bash
python3 scripts/build-official-update.py \
  --sources updates/2026-10.sources.json --raw /path/archived-originals \
  --baseline /path/baseline/cache.db --output patches/2026
python3 -m unittest discover -s scripts -p "test_official_update.py"
node scripts/validate-patches.mjs
```

生成器校验原件和解析输入的哈希、整省乡级总数、名称唯一性及父级名称来源，再写入补丁。湖南10月公告补丁按原文6条明确代码单独维护，不从旧名猜测代码。

## 本批验证结果

- 江苏1346个四级节点、福建1203个四级节点，与此前独立提取的官方表逐条比对：代码、名称、父级均零差异，且无额外有效节点。
- 在重新物化的2026分区检查历史保留、19省级数量和有效四级父链；自动化测试覆盖旧年度不变、同码异名、缺少来源、重复省份、缺失基线、悬挂父级及完整性声明。
- 其余12省未写入未经核验的新全量补丁，继续保留原数据；这不意味着这些省份没有发生2026年调整。
